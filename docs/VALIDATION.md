测试日期：2026-10-13（Asia/Shanghai）。

设备：小米 15、HyperOS、Android 16。官方 CoolMarket 13.3.6 正常，按测试者要求未再次发布官方评论。

此前实际请求与单变量实验：

| 版本 / 对照 | 结果 |
|---|---|
| 原版 925abdb，Token 时间为科学计数法，使用此前错误的 ID 配置 | 业务失败 |
| 仅修复为整数秒、保留原 Device 和错误的 ID 配置 | 业务失败 |
| 整数秒 + 仅替换 Device 第 0 段 + 配套原 v2 Token | 业务成功，唯一新评论读回 |

| 仅删除 replyAndForward=0 | 失败 |
| 将有效首段编译进私有实验 APK，无 Hook | 新评论创建且读回 |

以上对照保留同 Cookie、公共 Header 和 Device 其余字段，定位到源码 szlmId / 数字联盟 ID 设置写入的位置。编译个人标识的私有实验 APK **不作为公开附件**。

## 使用者补充测试与结论更正

2026-10-13，使用者报告：在原版 925abdb 中保持原时间代码，仅将“数字联盟 ID”设置改为本人从酷安官方检测日志取得的 36 位 ShuzlmID 后，即可回复。此项为使用者手动测试反馈，没有新增 Hook 抓包或独立读回记录。

| 版本 / 对照 | 结果与证据来源 |
|---|---|
| 原版 925abdb，保持原时间代码，仅填入本人正确 ShuzlmID | 评论成功；使用者手动测试反馈 |

新测试补足了此前未测试的“原时间代码 + 有效首段”组合。因此，在本次设备与账号测试中，错误的数字联盟 ID 配置是此前评论失败的关键原因；正确配置 ShuzlmID 即可恢复回复，整数秒修改不是必要条件。该结论不应表述为“时间格式与 Device 第 0 段均必须修复”。整数秒改动作为时间格式规范化保留，不据此推断服务端是否始终接受所有时间格式。

使用者确认的获取步骤：酷安官方 App → 设置 → 关于 → 右上角三点 → 检测日志 → 连点“复制 OAID”4 下，粘贴后找 `ShuzlmID`。填写日志中的 ShuzlmID，而非 OAID；这里不公开本人标识的实际值。

本次公开候选 APK 改为运行时配置，验收状态和精确源码/APK 哈希见发布附件 `coolapk_github_release_validation.json`。接受一个本人已验证的有效值并不等于自动识别每位用户的 ID，也不能证明所有 36 位文本或所有设备账号都有效。

本次更正仅更新文档，原 Release APK、源码 tag 及校验值保留。没有伪造官方返回，也没有在公开资料中包含 Cookie、Token、原始设备标识或未脱敏抓包。
